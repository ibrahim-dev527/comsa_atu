Supabase Setup Guide
Full SQL schema + configuration instructions
⚠️
Complete these steps once before using the admin dashboard. After setup, all website content will be controlled from this panel.
🔧 Connection & Auth Tester
Click the button below to test your Supabase connection and verify your login token is active. Results appear below.

          

        


        
        

          
Step 1 — Create Supabase Project

          

            
1. Go to supabase.com → Create a new project named comsa-atu

            
2. Pick a strong database password and save it somewhere safe

            
3. Go to Project Settings → API and copy your Project URL and anon/public key

            
4. Open this file (admin.html) in a code editor and find the CONFIG section at the top of the <script> and fill in those two values

            
5. Do the same for events.html, blog.html, and past-questions.html — each one has a CONFIG section at the top of its script

          

        


        
        

          
Step 2 — Run SQL in Supabase SQL Editor

          

            
Go to your Supabase project → SQL Editor → paste and run the following:

            
-- EVENTS TABLE
CREATE TABLE events (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  title       text NOT NULL,
  description text,
  category    text,
  event_date  date NOT NULL,
  event_time  text,
  venue       text,
  audience    text,
  status      text DEFAULT 'upcoming',
  icon        text DEFAULT '🎉',
  image_url   text,
  week_group  text,
  created_at  timestamptz DEFAULT now()
);

-- BLOG POSTS TABLE
CREATE TABLE posts (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  title       text NOT NULL,
  excerpt     text,
  content     text,
  category    text DEFAULT 'news',
  author      text DEFAULT 'COMSA Secretariat',
  image_url   text,
  is_featured boolean DEFAULT false,
  tags        text[],
  created_at  timestamptz DEFAULT now()
);

-- PAST QUESTIONS TABLE
CREATE TABLE past_questions (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  course_title text NOT NULL,
  course_code  text,
  year_sem     text,
  programme    text,
  pdf_url      text,
  storage_path text,
  created_at   timestamptz DEFAULT now()
);

-- GALLERY PHOTOS TABLE
CREATE TABLE IF NOT EXISTS gallery_photos (
  id           uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  caption      text,
  image_url    text,
  storage_path text,
  created_at   timestamptz DEFAULT now()
);

-- ENABLE ROW LEVEL SECURITY
ALTER TABLE events ENABLE ROW LEVEL SECURITY;
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;
ALTER TABLE past_questions ENABLE ROW LEVEL SECURITY;
ALTER TABLE gallery_photos ENABLE ROW LEVEL SECURITY;

-- PUBLIC READ POLICIES (anyone can read)
CREATE POLICY "Public read events" ON events FOR SELECT USING (true);
CREATE POLICY "Public read posts" ON posts FOR SELECT USING (true);
CREATE POLICY "Public read past_questions" ON past_questions FOR SELECT USING (true);

-- ADMIN WRITE POLICIES (service_role key only — used server-side)
-- These allow the admin dashboard to insert/update/delete using the anon key
-- Write access requires a valid Supabase Auth JWT (only your logged-in admin account)
-- ADMIN WRITE: only authenticated Supabase users (your admin account)
CREATE POLICY "Auth write events" ON events
  FOR ALL USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "Auth write posts" ON posts
  FOR ALL USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "Auth write past_questions" ON past_questions
  FOR ALL USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "Public read gallery" ON gallery_photos FOR SELECT USING (true);
CREATE POLICY "Auth write gallery" ON gallery_photos
  FOR ALL USING (auth.role() = 'authenticated')
  WITH CHECK (auth.role() = 'authenticated');

          

        


        
        

          
Step 3 — Create Storage Buckets

          

            
In Supabase → Storage → New Bucket:

            
• Bucket name: past-questions → set to Public

            
• Bucket name: blog-images → set to Public

            
• Bucket name: gallery → set to Public

            
Then run this SQL to allow uploads:

            
INSERT INTO storage.buckets (id, name, public) VALUES
  ('past-questions', 'past-questions', true),
  ('blog-images', 'blog-images', true),
  ('gallery', 'gallery', true)
ON CONFLICT DO NOTHING;

CREATE POLICY "Public read storage" ON storage.objects
  FOR SELECT USING (bucket_id IN ('past-questions','blog-images','gallery'));

CREATE POLICY "Admin upload storage" ON storage.objects
  FOR INSERT WITH CHECK (true);

CREATE POLICY "Admin delete storage" ON storage.objects
  FOR DELETE USING (true);

Step 6 — Add Your Keys to All Pages

          

            
In each of these files, find the // ===== SUPABASE CONFIG ===== comment and fill in your URL and key:

            
• admin.html — this file (controls everything)

            
• events.html — reads events table

            
• blog.html — reads posts table

            
• past-questions.html — reads past_questions table

            
Example:

            
const SUPA_URL = 'https://xxxxxxxxxxx.supabase.co';
const SUPA_KEY = 'eyJhbGci...(your anon key)...';

          

        



        
        

          
Step 7 — Create Your Admin Account in Supabase Authentication

          

            
🔒
This admin panel now uses Supabase Authentication. Your email and password are managed entirely by Supabase — nothing is stored in any code file. Only verified users can write to the database.


            
Step 7a — Go to your Supabase project

            Open supabase.com → sign in → open your comsa-atu project.


            
Step 7b — Open Authentication → Users

            In the left sidebar click Authentication, then click Users in the sub-menu.


            
Step 7c — Add a new user

            Click the Invite user or Add user button (top right of the Users list).

            Enter your admin email and a strong password. Example:

            Email: admin@comsa-atu.gh

            Password: something only you know — minimum 8 characters

            Click Create User.


            
💡
Use the same email and password when you log in to this admin panel. If you forget your password, go back to Supabase → Authentication → Users → click your user → Reset Password. You never need to touch the code.


            
Step 7d — Confirm Email is not required (optional but recommended)

            Go to Authentication → Settings → Email. Turn off "Enable email confirmations" so you can log in immediately without needing to check your inbox.


            
✅
Once the user is created in Supabase, come back to this page, enter your email + password, and click Sign In. The RLS policies (Step 2) ensure only your authenticated account can add, edit, or delete content.
